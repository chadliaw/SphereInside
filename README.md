# SphereInside

把一個空間的「內部」印在多面體的「外部」。

站在空間中的一點，朝四面八方拍照；SphereInside 依每張照片拍攝時的仰角與方位，把照片貼到一個球內接多面體的每個三角形面上，最後輸出成可列印的展開圖。印出來、剪下、摺好、黏起來，手上就有一顆把整個空間包在表面上的多面體。

> **專案狀態：第一版可以運作。** 從手機拍攝到輸出展開圖的流程已經用真實照片跑通，但手持拍攝的照片對不齊，接縫明顯。詳見文末「現況」。

## 流程總覽

```
正二十面體 ──► 細分 ──► 多面體 (V, S) ──┐
                                        ├──► 各面著色 ──► 展開 ──► PDF
照片＋仰角＋方位 ──► 方向 → 顏色 ───────┘
```

三個階段：**生成多面體**、**貼上照片**、**展開輸出**，全部以 Python 實作；照片另由一個拍攝用的網頁取得。照片不需要先拼接成全景圖，而是由每個面直接到照片上取色。

## 安裝

需要 Python 3；目前只在 Python 3.14 上測試過。

```
pip install -r requirements.txt
```

在 Windows 上若沒有 `python` 指令，以下的 `python` 都改成 `py`。

## 使用方式

### 先用範例試跑

不必實際拍攝，先用合成的照片跑完整個流程：

```
python examples/make_demo.py
python -m sphereinside build examples/demo/meta.json -o examples/demo/demo.pdf
```

第一行會產生 46 張合成照片與對照檔，場景是一張畫了經緯線與方位標示的全景圖（`examples/demo/panorama.jpg`），方便檢查貼圖的位置與方向。第二行輸出三頁 A4 的展開圖。

### 實際拍攝

1. 用手機開啟拍攝網頁 [capture/index.html](capture/index.html)，朝四面八方拍照，直到畫面上的地圖全部變成綠色。詳見下方「拍攝」。
2. 在同一個網頁的「產生展開圖」選好面數、直徑與紙張，按「產生 PDF」，完成後下載。

合成是在瀏覽器裡進行的，照片不會上傳到任何地方。手機太慢或記憶體不足時，可以先按「下載照片與對照檔（ZIP）」，把 ZIP 傳到電腦，再用電腦的瀏覽器開啟同一個網頁、選擇這個 ZIP 來合成。

### 用命令列合成

也可以不經過網頁，直接在電腦上執行。把下載的 ZIP 解壓縮，裡面是照片與對照檔 `meta.json`：

```
python -m sphereinside check photos/meta.json
python -m sphereinside build photos/meta.json -o room.pdf
```

`build` 的選項：

| 選項 | 預設 | 說明 |
| --- | --- | --- |
| `-o`, `--output` | `sphereinside.pdf` | 輸出的 PDF 檔名 |
| `--level` | `1` | 細分輪數，面數為 20 × 3^level |
| `--diameter` | `150` | 外接球直徑（公釐） |
| `--paper` | `A4` | 紙張：`A4`、`A3`、`Letter` |
| `--dpi` | `300` | 貼圖的解析度 |
| `--margin` | `8` | 紙張邊界（公釐） |
| `--tab` | `5` | 黏貼耳高度（公釐） |
| `--allow-gaps` | | 照片沒有涵蓋所有方向時仍然輸出，缺的地方填灰色 |
| `--no-mirror` | | 不做鏡射 |
| `--png` | | 另外輸出每一頁的 PNG |

### 組裝

1. 以實際大小列印（不要縮放到符合頁面），建議用較厚的紙。
2. 沿實線剪下，沿虛線往印刷面的背面摺。
3. 邊上的數字兩兩成對：把黏貼耳黏到編號相同的那條邊的背面。

python -m unittest discover -s tests -t .

## 座標與符號

| 符號 | 意義 |
| --- | --- |
| `V` | 頂點集合，每個頂點是直角座標 `(x, y, z)` |
| `S` | 面集合，每個面是三個頂點 `(v_i, v_j, v_k)` |
| `r` | 到原點（球心）的距離 |
| `θ` | 方位角：在 xy 平面上與 +x 軸的夾角，範圍 `(-π, π]` |
| `φ` | 極角：與 +z 軸的夾角，範圍 `[0, π]` |
| `g` | 黃金比例 `(1 + √5) / 2 ≈ 1.6180339887` |

黃金比例慣用的符號也是 φ，為了不與極角混淆，本文件與程式碼一律寫成 `g`。

```python
# 直角座標 → 球座標
r = sqrt(x**2 + y**2 + z**2)
θ = atan2(y, x)
φ = acos(z / r)
```

+z 朝正上方，+x 朝方位 0°。仰角 `e`（水平為 0，朝上為正）與極角的關係是 `φ = π/2 − e`。方位 `a` 沿用羅盤的習慣，從上方看順時針增加，所以 `θ = −a`。

## 1. 生成多面體

### 起點：正二十面體

12 個頂點為

```
V = { (±1, ±g, 0), (0, ±1, ±g), (±g, 0, ±1) }
```

這組座標的邊長恰為 2，所以面集合就是兩兩距離都等於 2 的三點組：

```
S = { (v_i, v_j, v_k) | d(v_i, v_j) = d(v_j, v_k) = d(v_i, v_k) = 2 }
```

共 20 個面。實作時要注意兩件事：

- 浮點數不能直接比較相等，要寫成 `abs(d − 2) < ε`。
- 這樣找到的三點組沒有順序。每個面的頂點要統一排成從外側看為逆時針，判斷方式是 `(v_j − v_i) × (v_k − v_i)` 與面的中心同向；後面的法向量與展開都依賴這個順序。

### 細分

每一輪分成兩步：先加頂點，再重建面。

**加頂點。** 對每個面 `s = (v_i, v_j, v_k)`：

1. 求幾何中心 `v_c = (v_i + v_j + v_k) / 3`。
2. 沿法向量把 `v_c` 往外推到球面上，得到 `v_o`，使 `|v_o| = |v_i|`。因為三個頂點到球心等距，法向量與 `v_c` 同方向，所以 `v_o = v_c · |v_i| / |v_c|`。
3. 把 `v_o` 加進 `V`。

**重建面。** 所有 `v_o` 都加完之後，丟掉舊的 `S`，取 `V` 的凸包，凸包的三角形面就是新的 `S`：

```python
S = scipy.spatial.ConvexHull(V).simplices
```

凸包正好滿足「每個新頂點與附近 5–6 個點組成三角形」的各項要求：

- **不會有谷線。** 凸包必然是凸的，每條邊都是山摺。
- **取近的點、角度合適。** 當所有點都在同一個球面上時，凸包等同於球面上的 Delaunay 三角剖分，它會在所有可能的連法中讓最小內角盡量大，也就自然避開細長的三角形。
- **不必逐點挑鄰居。** 連法由整組頂點一次決定，不需要為每個 `v_o` 個別設計規則。

幾何上發生的事情是：每個舊面的中心多了一個頂點，而舊的邊被換成連接兩側新頂點的邊。這種做法在網格細分裡稱為 √3 細分。

凸包回傳的三角形沒有統一的頂點順序，要像前面一樣重新排成從外側看為逆時針。

### 細分的結果

實際算過，每一輪面數變成三倍：

| 輪數 | 頂點 | 面 | 谷線 | 內角範圍 | 最長邊／最短邊 |
| --- | --- | --- | --- | --- | --- |
| 0 | 12 | 20 | 0 | 60.0° | 1.00 |
| 1 | 32 | 60 | 0 | 56.2°–67.7° | 1.11 |
| 2 | 92 | 180 | 0 | 54.7°–70.6° | 1.16 |
| 3 | 272 | 540 | 0 | 54.2°–71.6° | 1.24 |
| 4 | 812 | 1620 | 0 | 54.1°–71.9° | 1.32 |

原本的 12 個頂點始終連著 5 個面，其餘頂點都連著 6 個面。

面數要兼顧貼圖的變形與組裝的工夫：面越多越接近球，但要剪、要黏的邊也越多。

## 2. 貼上照片

### 輸入

每張照片附帶三項資訊：

| 項目 | 說明 |
| --- | --- |
| 方位 | 鏡頭中心朝向的方位角 |
| 仰角 | 鏡頭中心朝向的仰角 |
| 視角 | 鏡頭的水平視角（或等效焦距） |

仰角與方位決定照片的中心落在球面上的哪裡，視角決定它涵蓋多大的範圍；缺了視角就無法知道中心以外的像素各自朝向哪個方向。

相機左右傾斜時，還需要第四項：繞鏡頭軸的傾斜角。拍攝網頁會一併記錄。

### 照片：方向 → 顏色

每張照片原本記錄的是「像素 → 顏色」。配合拍攝方向，可以改寫成「方向 `(θ, φ)` → 顏色」：

1. 像素 `(u, v)` 相對於像面中央 `(c_x, c_y)` 的位移，加上以像素為單位的焦距 `f`，得到相機座標中的射線 `(u − c_x, v − c_y, f)`。
2. 用仰角、方位與傾斜組成的旋轉矩陣，把射線轉到世界座標。
3. 換成球座標，取 `(θ, φ)`。

其中 `f = (影像寬度 / 2) / tan(水平視角 / 2)`。

### 多面體：對每個面取色

```
for s in S:
    for p on s:
        (x, y, z) → (r, θ, φ)
        color(p) = 照片在方向 (θ, φ) 的顏色
```

實作上是把上一節的對應反過來用：由 `p` 的方向找出涵蓋它的照片，把方向轉回那張照片的相機座標、投影成像素位置，再取樣。這樣每個面上的每個像素都恰好取一次色，不會留下空洞。取色用的方向要先經過鏡射，見下方「鏡像」。

「`p` on `s`」的做法是直接使用展開圖：每個面在紙上的位置決定了它涵蓋哪些像素，每個像素的中心換回面上的空間點，就是一個 `p`。

### 對照檔

每張照片的拍攝方向記錄在 `meta.json`，角度以度為單位，檔案路徑相對於對照檔所在的資料夾：

```json
{
  "hfov": 51.08,
  "photos": [
    { "file": "001.jpg", "azimuth": 12.5, "elevation": -3.2, "roll": 1.4 },
    { "file": "002.jpg", "azimuth": 48.0, "elevation": -2.9, "roll": 0.7, "hfov": 51.08 }
  ]
}
```

| 欄位 | 說明 |
| --- | --- |
| `azimuth` | 鏡頭中心的方位，從上方看順時針增加（與羅盤相同） |
| `elevation` | 鏡頭中心的仰角，水平為 0，朝上為正 |
| `roll` | 相機繞鏡頭軸的傾斜，可省略 |
| `hfov` | 沿影像寬度方向的視角；可以每張各寫，或在最外層寫一個預設值 |

`hfov` 都沒寫時，會改從照片 EXIF 的 35mm 等效焦距換算。方位 0° 不必是真正的北方，各張照片之間一致即可。

### 拍攝

仰角與方位由拍攝網頁 [capture/index.html](capture/index.html) 記錄，因為一般相機 App 不會把仰角寫進照片。網頁是單一檔案、不需要伺服器端程式，每按一次快門就同時讀取方向感測器，把畫面與當下的方位、仰角、傾斜一起存下來。

- **必須透過 HTTPS 開啟。** 瀏覽器只在 HTTPS 網頁上提供相機與方向感測器，所以要把 `capture/` 放到支援 HTTPS 的靜態網站空間，再用手機開啟。iOS 還會跳出要求使用動作與方向感測器的確認。
- **視角要自己填。** 瀏覽器無法得知鏡頭的視角，開始前要輸入鏡頭長邊的視角，預設 65°。這個數字不準時，照片之間會對不齊。
- **涵蓋範圍即時顯示。** 地圖上紅色是還沒拍到的方向，綠色是已經拍到的方向。
- **輸出。** 可以直接在網頁上產生展開圖，或下載內含所有照片與 `meta.json` 的 ZIP。
- **在瀏覽器裡合成。** 網頁用 [Pyodide](https://pyodide.org/) 在瀏覽器裡執行本專案的 Python 程式，所以結果與命令列版相同。第一次使用要下載約 30 MB 的執行環境。

### 拍攝支架

手持拍攝時，鏡頭的位置會隨著手移動，近處的物體在相鄰的照片之間會錯開（視差），而且羅盤量到的方位有數度的誤差。[rig/](rig/README.md) 是一個 3D 列印的雙軸支架，用兩個 608 軸承讓手機繞著鏡頭旋轉，並以每 30° 一格的定位點決定方位，用來從源頭消除這兩種誤差。

### 涵蓋檢查

進入合成之前，先確認照片已經涵蓋所有方向；只要有任何方向沒有照片涵蓋，就停下來並指出缺的是哪裡，不產生有空白的成品。

檢查的方式是在球面上均勻取兩萬個方向，逐一確認至少落在一張照片的範圍內，再把缺漏的方向依方位與仰角每 30° 一格彙整回報。

### 重疊

同一個方向常被多張照片涵蓋。目前取鏡頭中心最接近該方向的那一張；依距離加權平均以淡化接縫的做法尚未實作。

### 鏡像

影像是從球心往外看到的，印在多面體外側再從外面看，左右會相反，所以要預先水平翻轉，讓文字從外面看是正的。

翻轉要對整個球一起做，而不是每張照片或每個面各自翻轉，否則相鄰的面會接不起來。做法是取色時把方向對一個鉛直面鏡射，也就是面上的點 `(x, y, z)` 改到方向 `(x, −y, z)` 去取色。

### 感測器誤差

手機的方位感測常有數度誤差，相鄰照片可能對不齊。目前直接採用記錄值，之後可以用重疊區域的特徵比對微調各張照片的方向。

## 3. 展開圖與輸出

面數多時整個多面體無法攤成不重疊的一片，一張紙也放不下，所以展開圖會拆成數片：

1. 建立面的相鄰關係（共用一條邊的兩個面相鄰）。
2. 從一個面開始，逐一把相鄰的面沿共用的邊攤到同一平面；會與已攤開的面重疊、或會超出紙張的面就先跳過。
3. 沒有面可以再加入時，這一片就完成了；從剩下的面另起一片，直到所有的面都用完。
4. 被剪開的每條邊給一個編號，並在其中一側加上黏貼耳。黏貼耳會與同一片的其他部分重疊時，改放另一側、縮短或壓低。
5. 把各片排進頁面，必要時旋轉 90°。
6. 對頁面上每個面涵蓋的像素取色，得到整頁的貼圖。
7. 輸出 PDF：貼圖是點陣圖，摺線（虛線）、裁切線（實線）與邊的編號是向量圖。

展開圖是從多面體外側看到的樣子，所有的摺線都往印刷面的背面摺。
